# Правила работы с репозиторием

Публичный репозиторий сайта «Журнал диспетчера / Карта станции» (GitHub Pages). Данные станции лежат в приватном `speed660/scada-data`; сюда их не копировать.

## Код правится только в `src/`

- `index.html` собирается скриптом и руками не правится. Исходники:
  - `src/page.html` — разметка;
  - `src/app.css` — стили;
  - `src/js/NN-имя.js` — код, склеивается по порядку номеров в один общий скрипт (порядок важен).
- После любой правки: `python build.py`, затем `python tests/run_all.py`. Коммитить и `src/`, и собранный `index.html`.
- В Content-Security-Policy вместо `'unsafe-inline'` стоит хеш SHA-256 скрипта, его считает `build.py`. Если поправить `index.html` руками, хеш не совпадёт, браузер не запустит скрипт и сайт перестанет работать. Тест `test_syntax.py` (`build.py --check`) это ловит.
- Встроенные обработчики в разметке (`onclick="…"`, `onerror="…"`) и `eval` не работают из-за CSP: обработчики вешать через `addEventListener`.

## Безопасность

- Любой текст из данных (журнал, `map/*.json` из приватного репозитория) в разметку только через `esc()`; числа — только после проверки, что это числа. Писать в эти файлы может любой, у кого есть токен.
- Секреты (токены, пароли, заголовки SCADA) не записывать ни в код, ни в тесты, ни в коммиты. Тесты работают на выдуманных данных из `tests/fixtures/`.

## Перед пушем

- В проект могут коммитить несколько сессий. Перед пушем: `git fetch origin main` и проверить, нет ли новых коммитов; если есть — сначала подтянуть их, пересобрать и прогнать тесты.
- Историю решений вести в `HISTORY.md` приватного репозитория `scada-data`.
