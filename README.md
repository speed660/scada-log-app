# Журнал диспетчера

Одностраничное приложение для диспетчера солнечной станции: журнал звонков с поля, база работников и подсказка угла трекера по положению солнца. Работает целиком в браузере, весь код в одном файле `index.html`.

Страница: https://speed660.github.io/scada-log-app/

## Что умеет

- **Журнал звонков по дням.** Кто звонил, устройство, номер и место, что просили, угол, время звонка, примечание. Лента суток показывает, когда были звонки.
- **Работники.** База с именами и телефонами. Номер вводится по маске `+998 XX XXX XX XX`, неполный номер не сохраняется.
- **Вернуть в исходное.** Отметка «Потом вернуть в исходное состояние» ставит запись в список «Ожидают возврата», пока устройство не вернули. Если возврата ждут дольше заданного времени (по умолчанию 2 часа, меняется в Меню → Настройки, 0 отключает), запись подсвечивается красным, а в заголовке вкладки появляется число просроченных.
- **Кто записал.** В форме есть поле «Диспетчер». Имя запоминается в браузере и сохраняется в каждой записи. Оно видно в карточке и в столбце «Записал» в Excel. Без имени запись не сохраняется.
- **Угол по солнцу.** При действии «Изменение угла» под полем угла показывается рекомендуемый угол на время звонка (трекер с одной горизонтальной осью), кнопки «К восходу» и «К закату», высота и азимут солнца, время восхода и заката. Станция настраивается в Меню → Настройки → «Станция и трекеры»: координаты, предельный угол, знак угла в SCADA, GCR для backtracking и поворот рядов от линии север–юг. Если координаты не заданы, расчёт идёт для Ташкента. Наклон участка вдоль и поперёк рядов не учитывается.
- **Сверка со SCADA.** Там же есть блок «Сверка угла со SCADA»: добавьте 3–4 точки (время и угол, который показывала SCADA), и приложение покажет расчёт, разницу и среднюю ошибку. Кнопка «Подобрать поворот рядов» ищет поворот, при котором расчёт совпадает с SCADA лучше всего, и подсказывает, если знак угла в настройках обратный.
- **Excel и резервная копия.** Журнал можно скачать таблицей `.xlsx` или копией `.json`.

## Правила для записей

- Сегодняшние записи можно править кнопкой «Изменить». Перенести их на другой день нельзя.
- Записи прошлых дней открываются только для просмотра. «Изменить» у них нет. «Повторить» и «Вернуть» работают: они создают новую запись.
- Удалять записи нельзя.
- Каждая правка сегодняшней записи сохраняется в её истории: кто, когда, что было и что стало. Строка «Правок: N» в карточке раскрывает список. История видна и у записей прошлых дней. При синхронизации истории правок с разных компьютеров объединяются.
- День записи определяется датой звонка, а не временем, когда её внесли. В полночь вчерашние записи закрываются.

Это правила интерфейса, а не защита от подделки: тот, у кого есть доступ к файлу данных, может изменить его напрямую. Если данные хранятся в GitHub, история коммитов показывает, кто и когда менял файл.

## Где лежат данные

По умолчанию данные хранятся в браузере этого компьютера. Дополнительно можно включить:

- **Рабочий файл** на компьютере (Chrome и Edge). Каждая запись сохраняется в него автоматически.
- **GitHub.** Журнал синхронизируется с файлом `scada-log.json` в приватном репозитории, и несколько диспетчеров видят записи друг друга.

В этом репозитории (`scada-log-app`) данных нет и быть не должно: он публичный, и в журнале имена и телефоны работников.

## Синхронизация с GitHub

1. Создайте отдельный **приватный** репозиторий для данных, например `scada-data`, и добавьте в него `README`.
2. GitHub → Settings → Developer settings → Fine-grained tokens → Generate new token. Доступ только к этому репозиторию, право Contents: Read and write. Для каждого диспетчера свой токен.
3. Откройте страницу, Меню → Данные → GitHub. Введите `владелец/репозиторий`, токен и придуманный пароль (не короче 8 символов), нажмите «Подключить».
4. На других компьютерах повторите шаг 3.

Как это работает:

- Изменение уходит в GitHub через 1,5 секунды одним коммитом. Новые записи других диспетчеров подтягиваются раз в минуту.
- При одновременной записи версии сливаются без потерь.
- Без связи журнал работает в браузере и отправляет накопленное, когда связь вернётся.
- На время подключения, ручной синхронизации и первой загрузки экран блокируется загрузчиком. Ожидание ответа GitHub ограничено 15 секундами, при ошибке можно повторить.

## Безопасность

- Токен хранится в браузере только в зашифрованном виде (AES-GCM, ключ из пароля через PBKDF2-SHA256, 600 000 итераций). Расшифрованный токен живёт в памяти вкладки и пропадает при закрытии страницы, перезагрузке и нажатии «Заблокировать».
- После перезагрузки страница просит пароль. Без пароля журнал работает, но с GitHub не синхронизируется.
- Страница может обращаться только к `api.github.com` (Content-Security-Policy). Весь пользовательский текст экранируется.
- Токен не попадает в файл журнала и в резервную копию.
- При подключении публичного репозитория приложение предупреждает, что данные увидит любой.

## Публикация на GitHub Pages

Settings → Pages → Deploy from a branch → ветка `main`, папка `/ (root)`. Страница открывается по адресу `https://<имя>.github.io/scada-log-app/`. Обновление страницы: заменить `index.html` и сделать коммит.

## Проверки

В папке `tests/` лежат автоматические проверки в браузере Chromium: вёрстка, маска телефона, правила записей, история правок, расчёт солнца (угол трекера сверяется с независимым перебором, восход и закат со справочником), сверка со SCADA и синхронизация с GitHub на имитации API. Данные в них вымышленные.

Запуск на своём компьютере (нужны Python, Node.js и Playwright):

```
pip install playwright
python -m playwright install chromium
python tests/run_all.py
```

GitHub Actions (`.github/workflows/check.yml`) запускает те же проверки при каждом коммите в `main` и при каждом pull request. Красная отметка у коммита значит, что в `index.html` что-то сломано. Сама публикация Pages от этого не блокируется: чтобы блокировать, нужно переключить Settings → Pages → Source на «GitHub Actions» и добавить в workflow шаг публикации.

## Файлы

- `index.html`: всё приложение (разметка, стили, код).
- `tests/`: автоматические проверки.
- `.github/workflows/check.yml`: запуск проверок на GitHub.
- `README.md`: это описание.
